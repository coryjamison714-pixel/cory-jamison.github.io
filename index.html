EGM Manager

A full-stack operations platform for the casino and arcade. Floor maps, every machine, staff, permissions, inventory and service history live in one shared system.

The problem

Machine records, floor layouts and repair history were spread across spreadsheets and people's memory. Slot techs couldn't see what changed on the floor or who changed it, and the casino and arcade teams track different things in different words.

What I built
  • Interactive floor maps. Canvas-based maps with zoom, pan, rotate, drag-and-drop placement and grouping. Grouped machine banks keep their relative positions, and one machine can still move on its own inside a group.
  • 3D cabinet inspection. A custom WebGL2 renderer, with no Three.js, loads vendor GLB models for Aristocrat, Everi, IGT, Konami and Light & Wonder. Techs click a part of the cabinet to open its record, and a service drawer slides out the bill validator, ticket printer, logic box and power supply.
  • Granular access control. Permissions combine account roles, job groups, floor access and per-person overrides. The server enforces them, and the interface reflects them.
  • Multi-user sync. Revision-based conflict detection catches concurrent edits, and request IDs make retries idempotent. A change notification bell shows who changed what across games, projects and the floor map.
  • Spreadsheet import. One import fills asset, serial, bank, IP, MAC, VLAN, switch and port details for every game and places each one by location, with warnings for duplicate IPs and MACs.

SportsView

An AI-controlled AV automation platform. It puts the right games on the right screens on its own, and staff can run the whole venue in plain English.

The problem

A sports venue has dozens of TVs, video walls, DirecTV receivers and audio zones, each with its own vendor control. Staff were routing games by hand during the busiest hours, and nothing tied the TV schedule to what was actually on each screen.

What I built
  • Routing engine. It schedules programming to displays and video wall tiles automatically. Event holds and media assignments are handled, and a manual operator choice is never overwritten by automation.
  • Echo, a natural-language control layer. Staff type requests like "put the Chiefs game on the main wall at 7." Echo, built on Amazon Bedrock, turns that into whitelisted, structured actions. Anything scheduled waits for a confirm step before it runs.
  • Reverse-engineered integrations. I connected SAVI video routing over GraphQL, DirecTV receivers over their local HTTP interface, and TVs by reading vendor docs and inspecting browser network traffic.
  • Verified device control. Every command checks the physical device state after the "success" response. Timeout handling never sends a command twice.
  • Zone audio and media. Per-zone source selection, volume and mute, plus image and looping-video delivery with restore-to-previous-source.

Simulcast Manager

It turns the weekly race-track calendar PDF into an approved broadcast schedule and prints the guides tellers and managers use on the floor.

The problem

Each week a manager rebuilt the simulcast schedule by hand in Excel from the United Tote calendar. That meant every track, post time, receiver box and channel, and it was easy to double-book a channel or miss an overnight race.

What I built
  • PDF import. It reads the United Tote weekly calendar, converts AM/PM post times, and keeps unknown tracks visible until they're mapped or excluded with a reason. Scanned PDFs and unrecognized layouts are refused rather than guessed at.
  • Conflict checks. It catches overlapping broadcasts on the same channel, with a configurable switch buffer, overnight finishes that cross midnight, uncovered days and missing assignments. A confirmed overlap blocks approval.
  • Receiver availability finder. When editing a track, it shows which Roberts boxes are free for that broadcast window or for the whole day. The RCN number stays fixed, and the lookup never writes data.
  • Approval workflow. Edits stay in a draft until a manager saves three checks and approves. Each approved revision is an immutable snapshot with a receipt and a history entry.
  • Printed outputs. Teller Guide, Manager Setup Guide, Weekly Calendar and CSV export, always built from the last approved revision, with estimated finish times clearly labeled.

AI development

Building AI that controls real equipment in a live venue.

Echo is the natural-language layer I built into SportsView. Staff type what they want, the way they'd say it to a coworker. Echo works out which screens, sources, zones and times they mean, using the live state of the venue, and turns the request into a plan the engine can run.

The hard part isn't getting a language model to answer. It's making sure a wrong answer can never do damage. So Echo can only propose actions from an approved list. Anything that changes the schedule waits for a person to confirm it, and the routing engine still owns every safety decision.

What Echo can do
  • Multi-step plans. One sentence can become several safe UI, map and routing actions, run in order.
  • Scheduled Event Mode. Echo fills in the source, walls, date and time from the live venue, pre-fills the Event Mode form, and waits for "confirm" or "cancel".
  • Zone audio. Set volume, mute and relative changes like "turn the patio up a little" across audio zones.
Guardrails I designed
  • Structured output only. Echo returns whitelisted actions and never raw code or scripts.
  • Sanitized context. The model never sees credentials, tokens, raw config or network addresses.
  • People stay in charge. Manual operator choices always beat automation, and schedule changes need confirmation.
  • Staged rollout. Each capability was built as its own stage, tested in a demo sandbox, and signed off in a PASS/FAIL log before going live.

How I build

The same habits run through all three projects.

Start on the floor, not in the editor

I work in the building these tools serve. Requests from techs, tellers and managers become specific fields, permissions and screens, and I test with the people who will use them.

Verify against the real world

A passing test isn't the finish line. I confirm that the TV changed, the speaker responded and the printout matches the workbook.

Small, reversible changes

I back up before every release, use Git history, keep database snapshots and hash release manifests, so any change can be traced and rolled back.

Write for the people on shift

Every system ships with guides staff actually use: START HERE sheets, an in-app Help & Guide and manager trial checklists. Confirmation steps are built into the screens.
